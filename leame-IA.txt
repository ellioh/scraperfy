PROPOSITO DEL PROYECTO
--------------------------------------------------------------------------------
Scraperfy es un SaaS de web scraping como servicio dirigido a empresas en Peru
y Latinoamerica. El sitio funciona como landing page de producto, catalogo de
servicios de extraccion de datos, blog tecnico sobre scraping y captacion de
leads/clientes.

Los "productos" son servicios de scraping (extraccion unica, monitoreo mensual,
dataset a medida, enterprise), no productos fisicos. El flujo de conversion es:
visitante → contacto/cotizacion, no e-commerce con carrito/pago.

URL de produccion: https://scraperfy.com
Repositorio:       https://github.com/ellioh/scraperfy
Rama principal:    main

El dueno del proyecto trabaja tambien en hleon-dev, compara2-back y
compara2-front. Cuando se pide hacer cambios aqui, el contexto es este
repositorio unicamente.


STACK TECNICO
--------------------------------------------------------------------------------
- Framework:      Next.js 15.3.3 (App Router) con React 19
- Lenguaje:       TypeScript 5 (strict mode)
- Estilos:        Tailwind CSS 3 — sin CSS modules, sin styled-components
- Base de datos:  MySQL / MariaDB con el driver mysql2 (SQL directo, sin ORM)
- Automatizacion: n8n por webhook (opcional), ver lib/n8n.ts
- Autenticacion:  Cookie httpOnly propia (sin NextAuth, sin JWT de terceros)
- Dependencias:   next + react + react-dom + mysql2 (sin librerias de UI externas)
- Markdown:       Renderer propio en lib/markdown.ts (sin remark, sin marked)
- Deploy:         Vercel (inferido por estructura; sin config especial)

Comandos:
  npm run dev     — servidor de desarrollo en http://localhost:3000 (necesita MySQL)
  npm run build   — build de produccion (verifica TypeScript; NO necesita la BD)
  npm run start   — sirve el build de produccion
  npm run db:init — crea la BD y las tablas y siembra desde data/*.json (idempotente)
  npx tsc --noEmit — solo verificacion de tipos (sin emitir)

Setup local: copiar .env.example a .env.local, levantar MySQL/MariaDB (XAMPP sirve)
y correr npm run db:init. Si el puerto 3000 esta ocupado, Next usa el 3001.

AUTENTICACION DEL PANEL ADMIN
--------------------------------------------------------------------------------
Sistema propio sin librerias externas:

1. El usuario va a /admin y llena formulario con password
2. POST /api/admin/login — verifica contra env var ADMIN_PASSWORD
3. Si correcto: setea cookie httpOnly "scraperfy_admin_token" con token Base64
4. Token: Buffer.from(`${SECRET}:${Date.now()}`).toString("base64")
5. Verificacion: decoded.startsWith(`${SECRET}:`)
6. TODAS las rutas protegidas (paginas y API, incluidas /api/admin/blog/* y
   /api/admin/productos/*) llaman isAuthenticated() de lib/auth.ts

Variables de entorno necesarias (.env.local; plantilla completa en .env.example):
  ADMIN_PASSWORD=tu-password-seguro
  ADMIN_TOKEN_SECRET=minimo-32-caracteres-aleatorios
  DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME, DB_SSL, DB_POOL_SIZE
  N8N_WEBHOOK_URL, N8N_WEBHOOK_SECRET   (opcionales)

Nota: ADMIN_SECRET ya no se usa. Antes las API de blog y productos comparaban
la cookie contra ADMIN_SECRET, lo que nunca coincidia con el token del login
(siempre 401). Corregido al unificar en isAuthenticated().


CAPA DE DATOS (MySQL / MariaDB)
--------------------------------------------------------------------------------
Tablas: posts, productos, solicitudes (ver db/schema.sql). Las columnas son
snake_case (fecha_publicacion, meta_descripcion...) y las interfaces TS son
camelCase: el mapeo esta en lib/blog.ts, lib/productos.ts y lib/data.ts.
- Los arrays (tags, caracteristicas) se guardan como JSON en columnas TEXT
  (portable entre MySQL y MariaDB, donde JSON es un alias de LONGTEXT).
- Fechas: DATETIME en UTC (pool con timezone "Z"); las funciones devuelven ISO 8601.
- precio es DECIMAL(10,2): mysql2 lo devuelve como string, se convierte con Number().
- Solo funciona en server components y API routes (usa mysql2).

TODAS las funciones son async: siempre usar await.
NUNCA importar lib/blog.ts, lib/data.ts o lib/productos.ts en "use client".

Patrones de uso:

  // Blog
  const posts    = await getPosts();           // solo publicados
  const posts    = await getPosts(false);      // todos (para admin)
  const post     = await getPost("mi-slug");
  const post     = await getPostById("123");
  await savePost({ titulo, slug, ... })        // INSERT si no existe el id, UPDATE si existe
  await deletePost("123")

  // Productos
  const prods    = await getProductos();       // solo activos (soloActivos=true por defecto)
  const prods    = await getProductos(false);  // todos incluyendo inactivos (para admin)
  const prod     = await getProductoById("svc-001");
  await saveProducto({ nombre, ... })          // crea o actualiza
  await deleteProducto("svc-001")

  // Solicitudes
  const solic    = await getSolicitudes();
  await saveSolicitud({ nombre, email, ... })
  await marcarLeido("123")

IMPORTANTE (bug ya corregido): savePost NO usa INSERT ... ON DUPLICATE KEY UPDATE.
Ese patron se dispara con CUALQUIER clave unica (incluido slug) y sobrescribia
en silencio otro post con el mismo slug. Ahora un slug repetido falla con un
error claro ("Ya existe otro post con el slug ...", HTTP 400).

Migracion desde JSON: npm run db:init crea la BD y las tablas y siembra desde
data/*.json solo si las tablas estan vacias. Despues de eso, data/*.json ya no
se lee en runtime.

INTEGRACION n8n (lib/n8n.ts)
--------------------------------------------------------------------------------
Al guardar una solicitud en /api/contacto se hace POST a N8N_WEBHOOK_URL con
  { "evento": "solicitud.nueva", "solicitud": { id, nombre, email, empresa,
    url_objetivo, frecuencia, formato, descripcion, plan, fecha, leido } }
Si N8N_WEBHOOK_SECRET esta definido se envia como header X-Scraperfy-Secret
(en n8n: nodo Webhook > Authentication > Header Auth). Timeout 5s. Es
best-effort: si n8n no esta configurado o falla, se loguea el error y la
solicitud igual queda guardada; el visitante no ve ningun error.

PATRONES Y CONVENCIONES
--------------------------------------------------------------------------------
1. Server components por defecto. "use client" solo para formularios, useState,
   useEffect o event handlers.

2. La navbar (ScraperfyNav) es client component separado, importado en page.tsx
   para que page.tsx pueda ser server component y llamar a getPosts().

3. Rutas API admin siempre verifican autenticacion primero. Retorno estandar de
   error: { error: "No autorizado" } con status 401.

4. Las paginas y rutas que leen la BD llevan export const dynamic = "force-dynamic"
   (home, /servicios, /blog, /blog/[slug], /blog/categoria/[categoria],
   sitemap.ts, feed.xml, dashboard). No hay generateStaticParams: el contenido
   se edita desde el admin y el build no debe depender de la BD.
   generateMetadata para SEO dinamico por pagina.

5. IDs de posts: strings como "post-001". IDs de productos: strings como
   "svc-001". Nuevos registros via admin usan Date.now().toString().

6. No hay imagenes de posts. Si se agregan, usar Next.js Image con alt.

7. Tailwind exclusivamente. Sin estilos inline. Sin @apply en CSS.

8. Todo el contenido es en espanol (es-PE como locale en fechas y textos).

9. Para agregar una nueva pagina publica: crear app/nueva-pagina/page.tsx
   como server component. Si necesita datos, importar de lib/*.ts directamente.
   Agregar la ruta al sitemap en app/sitemap.ts.

ERRORES COMUNES Y SOLUCIONES
--------------------------------------------------------------------------------
Error: "You're importing a component that needs ... only works in a Client Component"
Causa: Importar lib/blog.ts, lib/productos.ts, etc. en un "use client"
Solucion: Mover la logica de datos a un server component padre o API route.

Error: TypeScript - tipo union no asignable al tipo literal
Ejemplo: tipo "unico" | "mensual" | "cotizar" no asignable a "unico"
Solucion: Declarar el tipo explicitamente:
  type Tipo = "unico" | "mensual" | "cotizar";
  const [form, setForm] = useState<{ tipo: Tipo; ... }>({ tipo: "unico" })

Error: productos/page.tsx form no muestra el producto al editar
Verificar: que setMostrarForm(true) se llame en iniciarEdicion().

Error: 401 al llamar a /api/admin/blog o /api/admin/productos desde el admin
Causa posible: sesion vencida (cookie de 8h) o ADMIN_TOKEN_SECRET distinto al
usado al iniciar sesion. Volver a iniciar sesion en /admin.

Error: /blog/categoria/casos de uso — URL con espacio
El slug de categoria se genera con encodeURIComponent en los links.
La ruta usa decodeURIComponent para recuperar el nombre original.
Si hay problemas, simplificar nombres de categorias (sin espacios ni acentos).

DESPLIEGUE EN VPS: ver DEPLOY.md (Docker Compose recomendado, o Node+PM2+nginx).
Archivos: Dockerfile (stages deps/build/migrate/runner), docker-compose.yml
(mysql + migrate + app + caddy con perfil "proxy"), Caddyfile, .env.vps.example.
next.config.ts: output "standalone" y serverExternalPackages ["mysql2"] (sin esto
mysql2 queda empaquetado en un chunk y sus require dinamicos pueden fallar).
En produccion la cookie de sesion es Secure: el admin solo funciona por HTTPS.

Vercel no aloja MySQL: hace falta una BD accesible por internet (VPS propio,
Aiven, Railway, TiDB Cloud, etc.). Correr npm run db:init UNA vez apuntando a
esa BD (con las DB_* exportadas) antes del primer uso.
